Features

为什么选择 MaiMaiFramework

把散落的脚本收敛为一套约定：注册即生效，事件自动分发，插件之间互不侵入。

⚡

事件驱动的隐式调用

框架统一监听官方事件，你只需把方法注册到对应钩子，调用时机由框架负责，无需自己串联生命周期。

🧩

插件化注册

脚本以插件形式静态或动态载入，通过 Register / UnRegister 管理订阅，模块边界清晰。

🖥️

Game 与 UI 双端统一

同一套插件写法同时覆盖服务端 Game 与客户端 UI，减少重复代码与跨端沟通成本。

🔌

零侵入接入

只需在 project.json 中添加文件名，不必修改框架源码或游戏地图逻辑。

📦

可移植的脚本资产

遵循约定编写的插件可以在不同地图、不同作者之间直接复用，移植不再是重写。

🧠

面向非程序作者

下载即用的框架文件加简短配置，让地图作者无需理解 Lua 细节也能装配完整玩法。

Quick Start

三步接入现有工程

框架只能在 CSOL 缔造者游戏模式环境下运行。准备好文件后，在游戏模式中测试效果即可。

STEP 01

下载框架文件

获取 main 分支的 MaiMaiFramework.lua，放入 project.json 同目录。

STEP 02

修改 project.json

在 game 与 ui 数组中声明框架文件；有插件时按顺序追加文件名。

STEP 03

进入游戏模式验证

在 CSOL 缔造者中测试脚本效果，通过聊天框信号即可触发插件逻辑。

project.json仅框架
{
  "game": ["MaiMaiFramework.lua"],
  "ui":   ["MaiMaiFramework.lua"]
}
project.json+ 插件
{
  "game": ["MaiMaiFramework.lua", "AddHealthPlug.lua"],
  "ui":   ["MaiMaiFramework.lua", "AddHealthPlug.lua"]
}
Plugin Development

写一个插件，只需要注册

把方法挂到框架提供的钩子上，剩下的交给框架。聊天框输入「增加生命值100」，即可为玩家提升生命值。

  • ✓区分运行环境：用 Game / UI 变量判断当前执行端，同一文件可双端运行。
  • ✓注册到钩子：Framework 暴露 GamePlug 与 UIPlug，按需 Register。
  • ✓无需框架改动：插件独立成文件，随工程一起加载。
  • ✓随时解绑：调用 UnRegister 移除订阅，避免重复触发。
AddHealthPlug.luaLua
-- 编写插件
if Game then
  function MyGameFunc(player, msg)
    if string.find(msg, "增加生命值") then
      local value = string.gsub(msg, "增加生命值", "")
      player.health = player.health + tonumber(value)
    end
  end
end

if UI then
  function MyUIFunc(msg)
    UI.SignalPlus(msg)
  end
end

-- 注册方法到框架中
if Game then
  Framework.GamePlug.OnPlayerSignalPlus:Register(MyGameFunc)
end
if UI then
  Framework.UIPlug.OnChat:Register(MyUIFunc)
end
API Reference

可注册的事件钩子

框架在官方事件之上补充了扩展方法，例如在 OnUpdate 下一帧执行的 OnLaterUpdate。

服务端 Game

客户端 UI

OnRoundStart OnSpawn OnKilled OnChat OnInput OnKeyDown OnKeyUp OnSignal OnUpdate OnLaterUpdate OnSignalPlus
⚠
已知问题：同一个游戏 Lua 脚本中，Signal 与 SignalPlus 不能混用；Game 端与 UI 端同理。
